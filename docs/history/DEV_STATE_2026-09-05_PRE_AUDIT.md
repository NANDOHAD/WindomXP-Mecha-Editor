## 主要な決定事項

- `DEV_STATE.md`を実装着手時の最初の参照資料とし、その後に`docs/PROJECT_REFERENCE.md`、対象分野の詳細資料、一次コードを確認する。
- `.ani` / `.an2` / `.hod` / `Script.spt` / 暗号化`.x`・`.png`の形式、読み書き順、既存Inspector/APIを変更しない。
- AN2／単体HODの階層不整合読み込みは `treeDepth` を第一の正本とし、有効なら `childCount` を自動再計算する。`treeDepth` 自体が無効な場合だけ、有効な `childCount` から `treeDepth` を再構築する。フレーム階層列が異なる場合だけ一意な名前集合から構造順へ並べ替え、両方が無効、または全フレームを安全に同期できない場合は読み込みを中止する。
- 機体ファイルの先頭シグネチャが旧`ANI`なら、本読込み前に旧ANIのまま開くかAN2へ変換して開くかをユーザーへ確認する。変換時は元ANIを上書きせず、同じフォルダの空いている`.an2`／`.converted*.an2`へAN2方針の階層正規化を適用したコピーを保存し、公開ローダーで再読込みできたコピーを編集対象にする。元ANIと同じパス・既存ファイルは拒否し、旧ANI固有の未解析末尾がAN2コピーに含まれないことを確認文へ明記する。変換しない場合、旧`ANI`は読込時にHOD階層を自動修復せず、構造・全フレームの`treeDepth`／`childCount`とindex順を記録どおり維持する。不整合があっても表示と非構造編集を継続する。パーツ追加・削除を開始した時だけ、既知IKDATAまたは安全な末尾なし、構造と全フレームのパーツ数・index階層列一致を事前条件として限定正規化する。一方の階層列だけが有効なら確認後にその列を正本とし、両方が有効だが異なる場合は両プレビューから明示選択させ、両方無効・フレーム不一致・未知末尾は抑止を維持する。正規化と追加・削除は構造・全フレームを検証してから一括反映する。`ani2.save()`は旧`ANI`形式を維持し、旧HODに保存欄のない`unk1`〜`unk3`回転制約が現在の`rotation`と異なっていても保存を拒否せず、`rotation`をTRS行列へ書き出す。失われる制約値がある場合は警告を出し、保持が必要なら`ani2.saveAsAn2(filename)`を使う。固定長文字列・未編集HOD行列・未編集スクリプト本文・未知末尾を原バイトで保持する。基本200枠の後から`IKDATA`までが完全な旧アニメーション列なら拡張枠として読み込む。末尾まで厳密に`int32 length=13 + byte flag + Vector3 unk`列として解釈できる`IKDATA`は構造パーツindexへ適用し、数・順序・属性列の対応が変わった時だけ現在の全パーツ分へ再構築する。構造名の変更時も旧フレームHOD固有のラベルは変更しない。未知形式の末尾や旧形式に表現できない編集は保存前に拒否し、明示的な`ani2.saveAsAn2(filename)`を変換経路とする。旧ANI保存は一時ファイルの同期再読込検証後にだけ保存先を置換する。
- Phase 5のtraceは原作EXE観測値ではなく、実ANI/SPTをUnity Coreで実行した`RealAniObserved`基準値。原作一致とは扱わない。
- 原作EXEの`BURNERSET`第4文字列は`0x004A6E5C`で一時bufferへ読み取るだけで、`+0x26AC` frame名配列、`+0x26B4`第3float配列、機体生成、更新、描画のどこにも保存・比較・参照されない。Unityは編集互換のため原文を保持し、既知方向tokenだけ既存表示Adapterへ投影する。第4tokenを音声、長さ、太さ、alpha、fadeへ接続しない。
- 通常機体の`BURNER`は`+0xB74`要求byteで表示をgateし、SPT第3float配列`+0xE38`を描画値へそのまま渡す。ANI outputは別配列`+0xB7C`へ保存されるが観測済み通常描画call siteでは未使用で、`output=0`も表示要求を解除しない。速度倍率`value * max(speed * 10, 0)`は別constructorの`CShip`専用。Unityは通常表示からoutput倍率を除去し、`CShip`式を未接続の別Core関数として保持する。推進音の正output境界はUnity Audio Adapterとして分離する。
- Phase 6Aの原作観測traceは`observedFields`に列挙した値だけ比較し、未観測値を0として補わない。既存Phase 5 traceのtickは1始まりなので、取得CSVの0始まりindexと`tickOrigin=1`を分離して記録する。
- 原作観測は`Logs/WindomXP`を使用する。`ROBO/KD-03`のANI/SPT hashはプロジェクト内基準と完全一致し、原作観測ヘッダーとANI/SPT完全hashが一致するUnity基準だけを比較する。
- GT-001の原作`scriptedVelocity`は`FUN_004cd840`入口の保持率適用前Move、Unity側は要求変位へ使う値であり、同名でも処理段階が異なる。既存schema v1とRun 1～3は証拠として保持し、適用前Move・保持率・適用後Moveを分けた契約を追加してからCore合否を判定する。
- 2026-08-25以降、原作EXE観測は通常工程ではなく、一次資料だけで一意に決められない共有Core境界へ限定する。観測前に`Tools/OriginalTrace/OBSERVATION_TICKET_TEMPLATE.md`で疑問、処理段階、最小フィールド、成功条件、停止条件を固定する。
- 観測結果は`アンカー観測`、`適合trace`、`診断ログ`へ分離する。同一経路は2回一致を既定とし、2セッション連続で対象特定・入力・BP運用に失敗した場合は観測を止め、一次資料へ戻るか`原作高確度`／`Unity代替`へ降格する。
- UI言語は`Settings.txt`の2行目へ`Language=ja`または`Language=en`として保存する。既存の1行目（機体フォルダ）を維持し、旧1行形式も後方互換で読み込む。
